🟡 게이트 상태 해설 — 왜 WARN인가?

§7 IC 게이트 룰:

  • 🟢 OK — 최근 3개 측정값 전부 ≥ 0.05
  • 🟡 WARN — 최근 3개 중 하나라도 < 0.05 (또는 < 0.03)
  • 🔴 FREEZE — IC < 0.03 2회 연속 (자동 watch-only)
  • ⛔ LIQUIDATE — IC < 0.03 3회 연속 (신규 픽 차단, 인간 ack 필요)

지금 상태: 두 사이드 모두 last-3에 IC<0.03 슬롯이 섞여있어 WARN. 30일 평균 IC는 +0.196 (SHORT) / +0.139 (LONG)로 양호.

왜 노이즈? 단일 timestamp IC는 80~85개 코인에 대한 Spearman 상관 — 한 슬롯 단위로 보면 ±0.2까지 흔들림이 정상. 30일 평균/누적 win rate가 진짜 지표.

지금 액션 필요? 없음. FREEZE까지는 IC<0.03 연속이 필요한데 지금은 양수/음수 섞여 있음. 자동 시스템이 알아서 처리.

realized — net of fees

실현 손익이 0과 구분되는가

중요한 지표 먼저: 30일 동안 paper trade 원장(recommendation_ledger.csv)에 기록된 모든 entry→exit 가격 차이 → 비용 차감 후 평균 / Sharpe / t-stat. 비용은 SHORT 0.13% (Bitget perp 0.06%×2 + 평균 funding 0.01%/6h), WATCH_LONG 0.10% (Upbit spot 0.05%×2). t < 1.0이면 0과 구분 안 됨 — 더 많은 표본이 필요한 상태. Sharpe는 per-trade 기준 (annualize 안 함, 표본이 IID 아닌 cross-sectional).

holdout vs live

학습 시 holdout IC와 live IC 일치 검사

Phase 3 게이트(IC_live ≥ IC_holdout − 0.03) 만족 여부. live IC가 holdout보다 높으면 leakage / look-ahead 가능성, 낮으면 신호 약화 또는 distribution shift. holdout IC는 학습 시점(2026-04-25 F1)에 봉인된 값.

latest picks

최근 추천 — SHORT 5 / WATCH LONG 5

SHORT는 Bitget USDT-perp tradable 종목으로 5개. WATCH LONG은 Upbit 현물 또는 Bitget perp long으로 진입 가능한 5개 — 운영자가 수동 매매 기준이라 둘 다 actionable. actionable=False는 게이트가 watch-only로 전환된 상태(IC FREEZE 등). "WATCH" 라벨은 자동 basket 실행이 SHORT 쪽에만 연결돼있다는 의미이지 신호 품질이 약하다는 뜻이 아님 — 12h 2σ+ 적중 70.6%로 6h 64.6%보다 오히려 강함.

known limitations

알려진 한계 — 인터뷰어가 묻기 전에 먼저 말함

이 시스템이 아직 풀지 못한 문제들. 헤드라인 숫자는 이 한계 안에서만 의미가 있다.

01. 표본 + win/avg 불일치. 30일 ledger n=469 / 224. clustered t (rebalance window 단위) SHORT≈+0.33, LONG≈−0.27 — 둘 다 평균 수익이 0과 구분 안 됨. 그런데 SHORT win-rate 57.8% Wilson CI=[53.3%, 62.2%]는 50%를 제외해서 hit-rate 자체는 의미 있음. 결론: 작은 winner가 많은데 큰 loser가 평균을 잡아먹는 fat-tail 패턴. 90일 운영 후 재측정 + 손절 룰 추가 검토 필요. 헤드라인 IC는 t>10이지만 IC ≠ PnL이다.
02. 비용 모델이 단순하다. SHORT 0.13% / LONG 0.10% 고정 round-trip만 차감. 실제로는 호가 sparse 시 시장 충격 0.5~1.5% 추가 가능. ATR / 체결량 기반 비용 모델이 다음 단계.
03. regime 의존성 미검증. 학습/holdout 기간 모두 BTC 일정 구간 (2026-01~04). bear regime에서의 동작은 unobserved. regime-conditional 분석은 누적 데이터 부족으로 후순위.
04. 실행은 수동 매매 기준. SHORT 5는 Bitget USDT perp 매핑이 있고, LONG 5는 Upbit 현물 또는 Bitget perp long 둘 다 가능 — 운영자가 직접 매매하므로 둘 다 actionable. LONG 12h 2σ+ hit 70.6% > SHORT 6h 64.6%로 신호 품질도 LONG이 더 강하지만, 자동 basket 실행 인프라는 SHORT 쪽 (Bitget perp tradable 필터)이 먼저 구축됨. WATCH_LONG 표기는 "자동 실행 미연결" 의미이지 "신호 약함"이 아님.
05. σ-bucket calibration 다중 비교. 4개 σ 버킷 × 2 사이드 = 8개 그룹 hit-rate를 동시 검사 중. Bonferroni / BH 보정은 미적용. 단일 버킷 hit_rate 60% 같은 클레임은 multiple-testing exposure 있음.
06. IID 가정 회피. ① realized PnL은 동일 rebalance 내 5 picks가 같은 regime 공유 → naive t 대신 t_clustered (entry_time별 group → window 평균 → t) 헤드라인. ② IC time series는 lag-1 autocorr가 있어 단순 t를 과대평가 — t_ac = mean / (std/√N_eff)로 N_eff = N(1−ρ)/(1+ρ) 보정 표시. Sharpe annualize도 같은 이유로 안 함.
07. holdout 단일 분할. 마지막 20% 시간 구간 1개. walk-forward CV로 robust성 확인 필요. scripts/wf_holdout_harness.py는 있지만 6개 split 결과 안정성 추가 검증 중.
08. Survivorship bias 미처리. Upbit KRW 현재 listing만 학습. 과거 상폐 코인은 panel에서 빠져 historical EV가 부풀 가능성. Upbit 공시 archive로 historical universe 재구성은 backlog.
