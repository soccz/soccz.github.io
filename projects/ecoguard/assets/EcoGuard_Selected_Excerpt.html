01 · From OCR to evidence

OCR의 핵심은 ‘읽기’가 아니라, 흐트러진 원천 데이터를
설명 가능한 증빙으로 바꾸는 일이었다.

현업의 메모와 내부 양식은 누락·단위 혼용·자유로운 표현이 많습니다. 그래서 문자 인식률보다 값의 의미를 정리하고, 어디에서 왔는지 추적하며, 필요한 규정 근거와 연결하는 전처리에 집중했습니다.

STAGE 1 · RAW INTAKE

원천자료를 있는 그대로 받는다

스캔 문서, 자유 형식 메모, 표, 위치자료처럼 형태가 다른 입력을 접수합니다. 목표는 ‘깔끔한 문서라고 가정하지 않는 것’입니다.

  • 원본 파일과 줄·필드 위치 보존
  • 빈칸과 모호한 값을 임의로 채우지 않음

STAGE 2 · NORMALIZE

필드·단위·출처를 함께 구조화한다

같은 의미의 항목명을 통합하고 단위를 맞춥니다. 값마다 원본 위치를 남겨 계산 결과에서 원자료까지 되짚을 수 있게 설계했습니다.

  • 스키마·단위·범위 검사
  • source span·변환 이력·해시 추적

STAGE 3 · GROUND

문제를 EU 규정의 조문 근거와 연결한다

“문제가 있다”는 문장에 그치지 않고 관련 조문, 요구사항, 보완 행동을 함께 찾는 검색·근거 제시 구조를 준비했습니다.

  • 조문·문단 메타데이터와 citation
  • 근거 부족·도메인 밖 질문은 기권
유창한 답변보다 추적 가능한 답변법률 RAG는 그럴듯함이 아니라 근거 검색과 재현 가능한 평가로 봤습니다.
① Source lineage어느 파일·항목에서 왔는지 추적
② Schema checks필수값·단위·문서 간 불일치를 검사
③ Article retrieval정답 질문셋과 기권 사례로 평가
법무 관점 피드백: 자료를 규제 요구사항과 조문 근거로 연결하는 방향의 실무적 의미를 확인공식 인증·완전한 법률 검증 아님 · 합성 데이터 · 법률 자문 아님

02 · Reproducible technical core

정규화된 입력은 계산과 탐지를 반복 가능한 기술로 바꾼다.

모델 화면보다 중요한 것은 같은 입력에서 같은 결과가 나오고, 어떤 값과 가정이 결과를 만들었는지 설명할 수 있는가였습니다.

CBAM · DETERMINISTIC

추적 가능한
가격 민감도

CALCULATE
11단계 계산 DAG
피연산자·중간값·계보 보존
내재배출량 = sum(품목 중량 × 품목별 단위 내재배출)
유효가격 = max(인증서 가격 − 제3국 탄소가격, 0)
교육용 노출도 = 내재배출량 × 분석자 적용계수 × 유효가격
  • 입력 스키마와 단위 규칙 고정
  • 원자료→중간 계산 계보 보존
  • 손계산 기준값과 자동 테스트
  • 가정 변화 민감도 분리

구조 설명을 위한 교육용 계산입니다. 분석자 적용계수는 법정 phase-in 계수가 아니며 실제 신고액·인증서 의무·공식 산정값을 제공하지 않습니다.

FOREST · EVIDENCE PACK

합성 NDVI
변화 근거 묶음

EVIDENCE
36합성 셀 전부에 prediction·reference·confusion class 기록
NDVI 변화량 = NDVI(after) − NDVI(before)
후보 픽셀 = 이전 NDVI ≥ 0.45 그리고 변화량 ≤ −0.25
출력 = 픽셀 마스크 + 4방향 연속 영역 + GeoJSON·SVG
  • 합성 전후 band·NDVI 공개
  • TP·FP·FN·TN을 함께 기록
  • 연속 후보 영역 결정론적 계산
  • 탐지와 규제 판단 분리

작은 합성 정답셋에서 metric code path를 검사한 기준선입니다. 실제 위성 모델 성능, 현장 실사 또는 공식 EUDR 적합성 판정을 뜻하지 않습니다.

기술적 기준: 같은 합성 입력 · 같은 파라미터 · 같은 출력 · 중간값과 근거 보존공식 CBAM 계산·EUDR 판정 아님 · 교육용 PoC

03 · Proof journey

증명하고 나니
기술의 의미가
더 선명해졌다.

기능을 늘리는 일보다 데이터와 근거를 되짚을 수 있게 만드는 데 더 많은 시간을 썼습니다.

  1. 기술은 이미 있었다구조화·계산·변화 탐지·근거 검색을 하나의 흐름으로 연결했습니다.
  2. 그러나 맞다고 말하기 어려웠다정답 데이터, 규정 버전, 평가 기준이 함께 필요했습니다.
  3. 증명의 경로에 시간을 썼다출처 계보, 결정적 산식, 기준 질문과 판단 경계를 남겼습니다.
  4. 실무적 의미가 드러났다자동화보다 ‘왜 이 결과를 믿을 수 있는가’를 설명하는 기술이 중요했습니다.

Public boundary · 공개 범위와 구현 경계

재현 가능한 PoC
  • 합성 원천자료 정규화·입력 검증
  • 출처 위치와 변환 이력 추적
  • 조문 검색·citation·기권 평가
  • CBAM 교육용 결정론적 계산
  • 합성 NDVI reference 평가
화면에서 시뮬레이션
  • OCR 추출 완료 상태
  • 종합 품질점수와 보완 문구
  • 은행 심사역용 통합 보고 흐름
  • 업무 단계 간 자동 전달 경험
후속 검증·연동 필요
  • 실제 기업·은행 데이터 연동
  • 운영급 OCR·산림 모델 평가
  • 법률 전문가의 정답셋 관리
  • 규정·계수·가격 최신화

좋았던 점

  • OCR을 데이터 품질과 계보의 문제로 다시 정의했습니다.
  • 환경 분석을 비용과 검토 근거의 언어로 번역했습니다.
  • 각 주장에 확인 방법과 실패 경계를 붙였습니다.

남은 한계

  • 공개 예제는 작은 합성 자료 중심입니다.
  • 운영 성능과 실제 신고 적합성을 검증하지 않았습니다.
  • 규정 해석과 현장 확인에는 전문가 검토가 필요합니다.
