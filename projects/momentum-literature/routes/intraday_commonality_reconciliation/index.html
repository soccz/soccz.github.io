일중 commonality·reconciliation

commonality·forecast reconciliation의 추가 복잡성이 단순 일별·개별 예측보다 유효한가?

이 경로를 시작할 때

  • 종목별 일중 변동성의 공통성 또는 분해예측의 합계 일관성을 활용한다.
  • 패널·일중 입력과 추가 계산비용을 감당할 수 있다.

읽기와 판단 순서

  1. 출발

    08 · Volatility Forecasting with Machine Learning and Intraday Commonality14 · Exploiting Intraday Decompositions in Realized Volatility Forecasting - A Forecast Reconciliation Approach

    여기서 가져올 것

    • 종목패널의 intraday commonality를 ML feature로 쓰는 구조
    • 일중 분해별 base forecast를 일별 합계와 일관되게 조정하는 reconciliation
    • 원형에 필요한 패널·일중자료와 적응 가능한 검증 원리

    필요한 입력

    • 08 branch에는 동일 시각 grid의 종목별 intraday returns와 train-only common factor
    • 14 branch에는 분해 component와 aggregate RV의 정확한 회계적 합계 제약과 train-only reconciliation weight
    • 두 branch가 공유하는 target·origin·단순 HAR benchmark
    멈춤 조건공통성·조정 weight가 test 기간을 이용하거나 aggregate/component 정의가 일치하지 않는다.

    다음으로: 단순 base forecasts보다 안정적인 증분이 있으면 nonlinear spillover 확장과 비교한다.

  2. 확장

    26 · Forecasting Realized Volatility with Spillover Effects - Perspectives from Graph Neural Networks

    여기서 가져올 것

    • graph neural network로 nonlinear spillover를 반영하는 방법
    • 월 horizon에서 이득이 약해질 수 있는 반례

    필요한 입력

    • train-only graph와 node feature
    • 동일 HAR·linear reconciliation benchmark
    멈춤 조건GNN 이득이 graph의 미래정보·더 많은 feature·짧은 horizon에만 의존한다.

    다음으로: linear/commonality 기준을 넘는 증분만 refit·loss 공정성 gate로 이동한다.

  3. 예측 gate

    04 · HARd to beat: The overlooked impact of rolling windows in the era of machine learning

    여기서 가져올 것

    • rolling window·refit stride를 별도 treatment로 보고 강한 단순 benchmark와 공정하게 비교하는 규약

    필요한 입력

    • 동일 fitting window·forecast origin·refit 빈도·retune budget
    • 월 horizon의 QLIKE·MSE와 overlap·다중비교 처리
    멈춤 조건복잡한 후보의 이득이 더 잦은 refit·더 많은 feature·다른 평가월에서만 생긴다.

    다음으로: 공정한 forecast gate를 통과한 최소 후보만 비용 포함 경제성과로 이동한다.

  4. 경제성과 gate

    02 · The contribution of realized variance–covariance models to the economic value of volatility timing24 · A Multifactor Perspective on Volatility-Managed Portfolios

    여기서 가져올 것

    • 공분산 forecast를 실제 portfolio weight·turnover·비용 후 utility로 연결하는 방식
    • volatility management의 비용·factor exposure를 포함한 OOS 경제평가

    필요한 입력

    • forecast gate를 통과한 공통 월의 전략수익
    • 데이터·계산·거래비용과 portfolio exposure; covariance branch에는 사전 정의한 실제 배분 목적
    멈춤 조건통계적 증분이 비용 후 평가에서 사라지거나 covariance forecast를 사용할 실제 배분 목적이 없다.

    다음으로: 순경제가치가 있는 최소 commonality/reconciliation 구조만 확장으로 남긴다.

구현 체크리스트

  • 패널·component·aggregate의 시점과 단위를 맞춘다.
  • base forecast 뒤 08 commonality/pooling과 14 exact-sum reconciliation을 별도 branch로 검증하고, 각 선형 기준을 이긴 뒤에만 ML/GNN을 추가한다.
  • common factor·graph·weight는 train-only로 추정한다.
  • 월 horizon과 비용 후 결과를 핵심 판정으로 둔다.

금지할 추론

  • 일중 commonality를 현재 일별 WML 본선의 필수 입력으로 전제하지 않는다.
  • 합계 제약이 없는 6개 WML 자체를 14의 MinT reconciliation hierarchy로 묶지 않는다.
  • reconciliation의 회계적 일관성을 예측 우월성과 동일시하지 않는다.
  • 짧은 horizon의 GNN 우위를 월 horizon으로 자동 이전하지 않는다.
