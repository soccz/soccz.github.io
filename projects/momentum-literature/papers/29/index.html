Two Are Better Than One: Volatility Forecasting Using Multiplicative Component GARCH-MIDAS Models

Christian Conrad · Onno Kleen · 2020 · Journal of Applied Econometrics

핵심 예측필독추가자료 필요검수 완료독립검수 완료

30초 판정

빠른 일별 변동성과 느린 장기상태를 곱으로 분리하는 핵심 forecast 문헌이지만, 보고된 장기-horizon 우위에는 intraday RV와 실시간 VIX·거시 vintage가 필요하므로 현재 6개 WML에는 price-only 축소형 challenger로만 옮긴다.

사용할 때

  • 126일보다 긴 정보가 다음 달 WML 분산에 증분가치를 주는지 시험할 때
  • 단기 clustering과 느린 상태를 한 창의 평균이 아니라 두 component로 분리할 때
  • 거시변수의 발표지연·수정 vintage를 forecast 설계에 반영할 때

사용하지 말아야 할 때

  • 현재 price-only 자료로 housing-starts 원형의 재현을 주장할 때
  • 긴 정보가 모든 horizon에서 HAR보다 우월하다고 말할 때
  • Mincer–Zarnowitz R-squared를 forecast loss의 대용으로 쓸 때

한국 WML 변환기

고정

  • PIT KOSPI·12–2·6개 WML·월말 정보와 동일 BS15 mapping을 유지한다.
  • 빠른 WML 일별 component와 126일을 넘는 느린 component의 분리를 유지한다.
  • RW126·RW252·HAR를 복잡모형보다 먼저 평가한다.

교체

  • S&P 500 intraday RV target을 각 WML의 다음 달 일별 제곱수익 합으로 바꾼다.
  • 현재 단계에서는 VIX·NFCI·거시 vintage를 제외하고 최근 22일 WML variance의 K=264 Beta-MIDAS 또는 월별 12·24·36개월 slow component로 바꾼다.
  • 일별 overlapping horizon을 월말 next-month 비중첩 target으로 바꾼다.

현재 입력

  • 6개 WML 일별·월별수익
  • 월말 기준 126·252일 history
  • RW126·RW252·HAR benchmark와 동일 BS15 경제성과 함수

부족한 입력

  • intraday realized variance와 overnight 분리
  • 기간 전체의 VKOSPI·variance-risk-premium proxy
  • 한국 NFCI 유사 금융상태와 산업생산·주택자료의 실시간 vintage·발표 캘린더
  • 원 VOR Supporting Information의 optimizer·forecast recursion 세부와 재현 코드 실행

최소 구현 순서

  • RW126·RW252·HAR/log-HAR를 공통 OOS mask에서 먼저 고정한다.
  • price-only 사양의 X를 최근 22일 WML realized variance, K를 264로 사전 고정하고 실제 최초 raw-return 날짜를 기록한다.
  • 각 월말 training data로만 QMLE를 fit하고 경계값·수렴실패·fallback을 audit한다.
  • QLIKE·MSE·calibration과 동일 BS15 비용 후 Sharpe·최악월·turnover를 서로 다른 gate로 보고한다.

실패의 의미

price-only fast/slow 사양이 RW252·HAR를 이기지 못하면 현재 WML 가격정보에서 곱셈형 장기 component의 증분가치가 없다고 기록한다. 실시간 한국 거시정보의 가치까지 기각한 것은 아니다.

구현 단위검사

  • 월말 이후 수익 유입 차단 test
  • K=264 중첩 feature 최초일·timestamp test
  • forecast horizon 비중첩 test
  • rolling QMLE train-only test
  • optimizer convergence·fallback audit test
  • 공통 OOS mask와 동일 BS15 mapping test

주장 방화벽

허용 주장

  • S&P 500 VOR에서 multiplicative GARCH-MIDAS의 상대성과는 horizon별로 달랐고 housing starts 사양은 2·3개월 QLIKE에서 가장 강했다.

    이유: Table 6이 horizon별 최저 QLIKE와 MCS를 함께 보고한다. · 교정: 짧은 horizon의 HAR·realized-GARCH 우위와 필요한 intraday·실시간 외부자료 조건을 함께 쓴다. · 근거: p29_full_oos

  • 한국 6개 WML에는 126일을 넘는 price-only slow component를 사전등록 challenger로 시험할 수 있다.

    이유: 원문의 Beta-MIDAS 구조는 긴 lag를 저차원 weight로 축약한다. · 교정: 원형 재현이 아니라 price-only adapted multiplicative component라고 명명한다. · 근거: p29_components · p29_midas_weights

  • 거시 MIDAS OOS에는 당시 vintage와 발표지연이 필요하다.

    이유: Figure 6에서 final data와 real-time component 차이가 수치로 확인된다. · 교정: vintage가 없으면 거시사양을 주결과에서 제외한다. · 근거: p29_realtime

금지 주장

  • 긴 정보는 모든 horizon에서 HAR보다 우월하다.

    이유: 1일 최저 QLIKE와 유일한 MCS 생존자는 leverage HAR이고 중간 horizon은 realized GARCH가 강하다. · 교정: horizon별 승자와 loss를 분리한다. · 근거: p29_full_oos

  • 최종 수정 한국 거시자료로 만든 과거 forecast는 실시간 OOS다.

    이유: revision과 release lag가 당시 정보집합을 바꾼다. · 교정: vintage·발표 캘린더를 복원하거나 price-only 분석으로 제한한다. · 근거: p29_realtime

  • MZ R-squared가 크면 forecast accuracy도 높다.

    이유: 고변동 regime에서 R-squared와 forecast loss가 동시에 커질 수 있다. · 교정: QLIKE·MSE와 MCS 또는 block-bootstrap loss 차이를 사용한다. · 근거: p29_mz

  • QLIKE 개선은 BS15 Sharpe 개선을 보장한다.

    이유: VOR은 trading return·cost·Sharpe를 평가하지 않는다. · 교정: 동일 BS15 mapping의 경제성과를 별도 gate로 둔다. · 근거: p29_full_oos

문헌에서 해결되지 않은 항목

  • 본문 방법식의 5일·1주와 Table 6의 2주 horizon 표기는 일치하지 않아 Supporting Information·재현 코드를 대조하기 전 중간 horizon의 정확한 거래일 수를 고정하지 않는다.
  • 별도 Supporting Information의 초기값·optimizer·publication-lag 세부와 저자 패키지 결과는 이 근거 범위에서 재실행하지 않았다.
  • VOR의 첫 면에 CC Attribution-NonCommercial 고지가 있으나 이 프로젝트의 공개정책은 원문 파일을 호스팅하지 않는 link-only다.
