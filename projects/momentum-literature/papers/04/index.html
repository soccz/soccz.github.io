HARd to beat: The overlooked impact of rolling windows in the era of machine learning

Jonathan Chassot · Francesco Audrino · 2026 · International Journal of Forecasting

기준선필독적응 필요검수 완료독립검수 완료
이 페이지에서30초 판정문제와 답논증수식표 읽기한국 실험자가점검원문 위치

30초 판정

ML을 채택하기 전에 HAR의 rolling-window 길이와 refit stride를 공정하게 맞췄는지 감사하는 필수 benchmark 문헌이다.

사용할 때

  • HAR와 ML의 성능차가 모형 자체인지 update 규칙 차이인지 분리할 때
  • rolling window와 refit stride를 inner validation에서 고정할 때
  • forecast loss와 비용 후 utility를 같은 OOS에서 비교할 때

사용하지 말아야 할 때

  • static ML 대 daily-refit HAR 결과를 알고리즘만의 순수효과로 해석할 때
  • 좁은 RV/VIX feature 결과로 ML 일반의 무용성을 주장할 때
  • arXiv v1 수치를 2026 IJF 최종표로 인용할 때

문제

새 모델이 강해 보일 때 먼저 물어야 할 질문은 'HAR를 제대로 다시 맞췄는가'이다. 이 논문은 단순 기준선의 창 길이와 갱신주기만으로 순위가 크게 달라질 수 있음을 보여 준다.

중심 질문

합리적으로 선택한 rolling window와 자주 갱신한 HAR는 좁은 RV·VIX 정보집합에서 static 머신러닝보다 실제로 약한가?

기존 문헌의 빈틈

기존 ML 비교는 HAR의 fitting scheme을 충분히 보고하거나 튜닝하지 않아, 알고리즘 차이와 갱신규칙 차이가 뒤섞일 수 있었다.

논문의 답

저자 증거는 미국 주식 패널에서 HAR의 window와 특히 refit stride가 예측오차를 크게 바꾸며, 매일 갱신한 rolling HAR가 static ML보다 MSE·QLIKE와 비용 후 효용에서 강했다는 것이다. 연구자 해석은 ML이 무용하다는 것이 아니라 비교 기준선과 update 조건을 먼저 공정하게 맞추라는 것이다. 한국 월 WML에서는 각 월 origin에서 HAR와 challenger를 같은 주기로 다시 맞추는 비교를 main으로 두고, 계산비용 때문에 static하게 운용한 결과는 별도 operational robustness로 분리한다.

핵심 개념을 내 말로 바꾸기

rolling window

쉽게 말하면
항상 가장 최근의 고정 길이 자료만 남기고 오래된 관측을 버리며 다시 추정하는 창이다.

논문 안의 역할
구조변화에 적응하면서 기준모형 계수를 갱신한다.

흔한 오독
창 길이와 다시 맞추는 간격은 서로 다른 하이퍼파라미터다.

p04_window_heatmap · PDF 4쪽 · Figure 1 and Table 1

refit stride

쉽게 말하면
모형을 한 번 추정한 뒤 몇 예측을 그대로 쓰고 다시 추정할지를 뜻한다.

논문 안의 역할
새 위험정보가 계수에 반영되는 속도를 결정한다.

흔한 오독
같은 rolling window라도 stride가 다르면 같은 benchmark가 아니다.

p04_window_heatmap · PDF 4쪽 · Figure 1 and Table 1

OLS와 WLS HAR

쉽게 말하면
OLS는 오차제곱을 같은 비중으로, WLS는 관측별 중요도를 달리해 맞춘 HAR다.

논문 안의 역할
서로 다른 loss에 더 적합한 기준선을 제공한다.

흔한 오독
한 추정법의 승리를 HAR 전체의 절대 승리로 일반화하면 안 된다.

static ML

쉽게 말하면
시험기간이 시작되기 전에 학습한 모델을 시험기간 동안 다시 맞추지 않는 운용규칙이다.

논문 안의 역할
시험기간 중 재학습을 생략해 계산비용을 줄인 ML의 운용 비교조건이다.

흔한 오독
rolling HAR와의 차이를 알고리즘 함수형태의 순수효과라고 부르면 안 된다.

수식과 의사결정 규칙 해부 저자 방법 · 검토자 해설

수식은 암기 대상이 아니라 입력·출력·시점·실패 조건을 고정하는 계약입니다.

window·stride 선택규칙 · 시험구간에 들어가기 전에 창 길이와 재추정 간격의 격자를 비교해 예측오차가 가장 낮은 HAR 운용규칙을 고른다. 
selected_HAR_scheme = argmin_{window,stride} RMSE(window, stride) on the pre-test diagnostic sample
window
HAR 계수추정에 남기는 최근 관측기간
stride
한 번 추정한 뒤 다시 맞추기까지의 예측 간격
RMSE
Figure 1 heatmap에서 낮을수록 좋은 예측오차

직관: 같은 HAR 식도 과거관측을 얼마나 남기고 얼마나 자주 갱신하는지에 따라 실제 forecast 경로와 성능이 달라진다.

구현할 때: 후보 격자와 선택구간을 저장하고 outer test 결과로 window·stride를 다시 고르지 않는다.

realized utility (Equation 7) · 실현분산과 예측분산의 비율을 고정 Sharpe와 위험회피도 아래 효용으로 바꾸며, 예측과 실현 위험이 가까울수록 완전예측 효용에 가까워진다. 
RU_{i,t+1} = (SR^2 / gamma) × [sqrt(exp(RV_{i,t+1}) / exp(RV_hat_{i,t+1})) - 0.5 × exp(RV_{i,t+1}) / exp(RV_hat_{i,t+1})]
SR
논문이 40%로 고정한 투자기회의 Sharpe ratio
gamma
논문이 2로 고정한 투자자의 위험회피도
exp(RV) / exp(RV_hat)

표본과 입력

  • 균형 패널의 미국 개별주식 일중 실현변동성을 사용한다.
  • HAR는 다중시간척도와 선택적 시장위험, ML은 긴 RV lag와 선택적 시장위험을 쓴다.

예측대상과 시점

  • 오늘까지의 정보로 다음 거래일 log 실현변동성을 예측한다.
  • rolling HAR는 각 시험일 직전에 다시 맞추고 ML은 시험기간에 고정한다.

추정과 표본외 검증

  • 사전 진단구간에서 window와 stride를 고른 뒤 이후 시험구간을 평가한다.
  • ML hyperparameter는 시간상 앞선 validation에서 선택한다.

평가와 통과 기준

  • MSE와 QLIKE에 맞는 HAR 사양을 각각 비교한다.
  • MCS와 거래비용 전후 utility를 별도 결과층으로 둔다.

왜 작동하는가: 메커니즘과 반증 저자 제안 · 검토자 진단

저자가 제안한 작동 경로

  • 변동성 관계가 이동할 때 오래된 계수를 버리고 자주 다시 맞추는 단순 HAR가 최신 지속성 구조를 빠르게 흡수한다.

그 경로를 지지하는 관찰

  • window×stride heatmap의 급격한 성능차와 rolling HAR의 loss·utility 우위가 같은 메커니즘에 부합한다.

경쟁 설명

  • ML이 시험기간에 갱신되지 않았고 정보집합도 좁아서 update-frequency와 feature 제한이 HAR 우위를 만들었을 수 있다.

반증되려면 무엇이 보여야 하나

  • 같은 feature·같은 monthly refit의 ML이 한국 WML에서 강한 HAR를 안정적으로 이기면 HAR 우위의 한국 전이는 기각된다.

강건성·한계·빈칸 검토자 종합

버틴 결과

  • expanding window와 대형주 부분표본, 누적 오차, 비용 전후 utility에서 benchmark 강점을 재점검한다.

약해지는 조건

  • VIX의 이득은 모형과 시험 후반에 따라 달라지고 loss별 최적 HAR 추정법도 다르다.

검증하지 않은 것

  • 동일 rolling refit을 준 richer-feature ML과 한국 월별 WML의 비용 후 성과는 직접 시험하지 않는다.

내부 긴장과 해석 주의

  • 공정한 benchmark를 강조하지만 main 비교에서 HAR와 ML의 update 빈도는 동일하지 않다.

한국 6-WML 적용 실험실 프로젝트 적용안

원 논문을 복제하는 것이 아니라, 고정된 WML·RW126 기준선 안에서 검증 가능한 조각만 옮깁니다.

실험 순서

  • 여섯 WML의 공통 next-month risk target을 고정한다.
  • RW126과 HAR/LogHAR의 window·stride grid를 inner validation에서 비교한다.
  • 선택된 HAR를 각 outer month마다 다시 맞춘다.
  • lasso·RF에도 같은 origin과 refit 주기를 주어 main 비교를 만든다.
  • static challenger는 계산비용 비교용 별도 열로 둔다.
  • MSE·QLIKE·runtime 뒤 동일 BS15 비용 후 경제성과를 평가한다.

채택 기준

  • window·stride 선택에 outer test loss가 사용되지 않는다.
  • 모형 간 forecast origin·target·refit 날짜가 정확히 일치한다.
  • challenger가 강한 HAR의 예측 loss와 비용 후 경제성과를 모두 개선한다.

실패 진단

  • static만 나쁘면 알고리즘보다 update 빈도 문제로 분류한다.
  • 한 loss만 좋으면 loss-specific 개선으로 제한한다.
  • runtime 이득 없이 경제성과도 없으면 복잡모형을 제거한다.

한국 WML 변환기

고정

  • PIT KOSPI·12–2·6개 WML·월말 형성·다음 달 보유를 고정한다.
  • 모든 모델에 같은 outer forecast origin과 target months를 사용한다.
  • MSE·QLIKE와 BS15 경제성과를 별도 게이트로 유지한다.

교체

  • 미국 종목 다음날 RV를 한국 WML 다음달 일별 제곱수익 합으로 교체한다.
  • daily stride 1을 각 월 origin에서 refit하는 monthly stride 1로 교체한다.
  • VIX는 동일 시점 한국 공개 입력이 없으면 제외하고 no-VIX를 main으로 둔다.

현재 입력

  • 6개 WML의 일별·월별 수익
  • 월말 formation cutoff
  • RW126·HAR·LogHAR 기준선

부족한 입력

  • 미국 VIX와 동등한 장기 release-vintage 한국 위험지표
  • 종목별 bid–ask와 대차료를 결합한 전기간 비용

최소 구현 순서

  • inner past-only validation에서 HAR window와 stride를 먼저 선택한다.
  • HAR·lasso·RF를 동일 origin·refit 규칙에서 primary 비교한다.
  • static challenger는 계산비용을 포함한 operational robustness로 별도 보고한다.
  • 동일 forecast를 BS15 mapping에 넣어 Sharpe·CER·worst month·turnover를 비교한다.

실패의 의미

공정하게 맞춘 HAR를 ML이 common OOS loss와 비용 후 CER에서 모두 못 이기면 복잡성의 증분가치가 없는 것으로 기록한다.

구현 단위검사

  • forecast origin·feature cutoff·target month 날짜 폐쇄 test
  • window·stride 선택이 inner validation에만 의존하는 test
  • 모델 간 outer row-hash 동일성 test
  • future mutation에 대한 scaler·forecast prefix invariance test
