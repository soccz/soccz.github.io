v-next · 2026-05-31

v-next 재정의 — "맞히는 모델"에서 "좁혀주는 레이더"로

단일 ✓/✗ 예측을 내려놓고, 코인별 다음날 상승 확률분포와 하락 리스크를 표기해 후보를 좁혀주는 레이더로 재정의. 검증은 전부 OOS(purged walk-forward), leak 4/4 PASS(독립 재검증). 모든 수치는 거래비용 0.15% 왕복 차감 후. 아래는 요약이 아니라 진단 → 발굴 → regime 라이브러리 → 청산 검증 → 추천기 → 하방 → 스캐너 로 이어진 개선 과정 단계다.

① 진단 — 출발 문제: 레이더가 거의 침묵했다

구 엔진을 bear_quiet(약세·저변동 국면) regime 에서 돌리면 거의 아무 것도 안 불렀다. bear_quiet 침묵 recall ~6%, top-3 슬롯 93개(31일×3) 중 ACTIVE 가 단 1개. 그런데 같은 5월 시장에는 다음날 ≥15% 오른 코인이 84건 실제로 있었다. "안 부르는 게 안전"이 아니라 "기회를 통째로 놓치는" 상태 — 게이트가 아니라 task 정의를 다시 봐야 한다는 진단.

recall ~6% top-3 ACTIVE 1/93 슬롯 시장엔 ≥15% 84건

② 발굴 — leak-free 선행패턴

• 검증된 선행패턴(qv_surge · bounce_off_7d_low · short-momentum · ATR/RV). 단일 precursor OOS lift 3.5~4.7×(caseC), 다운사이드 자가검증 up20 top-decile 3.55×. 선행 lift 는 3.5~4.7× 대역으로 통일.
• 직관 3개가 데이터로 반전: ① range_contraction(조용→폭발) 역효과 ② 신고가 돌파 ≠ 선행(저점 반등이 선행) ③ low-cap 펌프 가설 반전(top50 대형이 base rate 1.5~3배 높음).
• cold 펌프(~54%, 첫 스파이크/신규상장)는 일봉으로 구조적 비예측. recall 천장 ~72%(top100). "bear 게이트만 풀면 된다"도 반증 — 완화 시 net −34%, 진짜 원인은 유니버스 컷(큰 펌프의 44%가 top100 거래대금 밖) + setup 희소.

단일 precursor 3.5~4.7× up20 top-decile 3.55× 게이트 완화 net −34%

③ regime 라이브러리 — lift 는 4 regime 모두 살아남으나, net 이 lift 를 뒤집는다

선행 lift 는 4 regime(bull/bear × quiet/volatile) 전부에서 살아남았다. 그런데 net 이 lift 를 뒤집었다: lift 가 가장 큰 volatile-hit regime 이 net 은 최악(pump-then-dump — 펌프를 잡았다가 다시 토해냄), 반대로 lift 가 평범한 곳이 net 은 멀쩡. 즉 진짜 lever 는 "무엇을 맞히느냐(lift)"가 아니라 "언제 빠지느냐(청산)"였다. 이 발견이 다음 단계(15m 청산 검증)를 강제했다.

lift 4 regime 생존 volatile hit↑ net↓ (pump-then-dump) 진짜 lever = 청산

④ 청산 검증 — 15m 경로로 손절/익절을 실증

• 하드 손절은 net 을 깎지만 하방을 캡한다: 하드 −5% 손절은 비용 포함 −5.15%로 실현돼 '깊은손실 빈도'를 오히려 늘렸고, −3% 손절이 진짜 하방 캡(거래당 worst −3.15%, 깊은붕괴 −10~−47% 를 전부 절단).
• 펌프의 수명: 잡은 펌프는 평균 15~20시간 안에 전개·소멸 — 하루 단위 보유가 합당.
• regime별로 청산이 net 을 살린 곳은 bear_quiet 만 marginal, 그조차 CI95 가 0 을 포함 → 통계적으로 reject 못함. 그래서 자동 채택이 아니라 SHADOW 로 forward 표본을 더 모은다.

−3% SL = 하방 캡 펌프 수명 15~20h bear_quiet marginal · CI95 0 포함 → SHADOW

⑤ 추천기 — 단일 ✓/✗ 대신 정직한 확률 분포

• precision@3 농축: 전체 OOS(rank-mean, 765일) ≈ 10%(base 1.67%, lift 5.9× ≈ 6배), 5월 backtest 11/93 = 11.8%(base 1.7%, ~7×). 둘 다 실측 — 윈도우를 함께 표기한다(전체 OOS ~10%/~6배, 5월 11.8%/7배).
• calibration 정직: 구 7-head 엔진의 +20% 과신(pred 60.3% vs 실제 11.6%, +48.7pp)을 새 스캐너에서 pred 5.7% vs 실제 6.0%(거의 일치)로 교정. (cal_xgb 7.5% 는 과신으로 탈락한 모델이라 헤드라인 아님.)
• 상승폭 magnitude(데이터로 검증): base rate up5 23% · up10 7.5% · up20 1.8% · up30 0.67%; 선행 top-decile up5 40.8% · up10 18.5% · up20 5.8%. → "+20% 다음날"은 선행 최상위에서도 ~6%, 50% 적중은 +3% 임계에서만, 운영 의사결정 임계 = +5~15%.

OOS ~10%/~6배 · 5월 11.8%/7배 과신 +48.7pp → 정직

시한부 판정의 정직한 산술 — 그리고 왜 그래도 게이트를 살렸나

v2 의 09-01 GO 기준은 verified closed n ≥ 200 인데, 계약 활성(07-27) 후 잔여 발사일 × 일일 캡 5건의 산술 상한은 175 < 200 — 즉 동결 조항 그대로면 KILL 이 산술적으로 확정돼 있다. 그럼에도 후보 생산 게이트를 수리한 이유: 무증거로 죽는 실험과 데이터로 판정받는 실험은 다르다. 전자는 아무것도 남기지 않지만, 후자는 다음 실험의 사전확률을 남긴다. 사전등록을 스스로 뒤집지 않는 것 — 그것이 이 페이지 전체가 지키려는 단 하나의 규율이다.

후일담 (2026-08-05): 판정은 09-01 까지 가지 않았다. 동결 조항의 조기 사망 규칙 — 누적 mean net 이 0 미만이면 마감일 전이라도 KILL — 이 verified closed 9건, mean −0.097% 에서 자동 발동했고, 판정문은 integrity hash 와 함께 박제됐다. 산술이 예고한 결말을 데이터가 27일 앞당겨 집행한 것이다. 게이트를 살린 보람은 그대로다: 이 실험은 무증거로 죽지 않았다.

09-01 KILL 산술 확정 (상한 175 < 200) → 08-05 조기 KILL 자동 집행 (동결 룰 · n=9 · mean −0.097%) 판정 기준 동결 유지 — 조작 없음

이 5주의 산출물은 모델이 아니다. 신뢰의 인프라다 — 알림이 실제 도달한 시각 이후의 성과만 재고, 산출물은 해시로 봉인되고, 실패는 시끄럽고, 판정은 사전등록 그대로 집행된다. 누적 negative result 22건+이 전부 재현 가능한 형태로 박제되어 있다는 것 — 그것이 이 프로젝트가 "좋아 보이는 백테스트"와 다른 점이다. 그 기계의 실물이 바로 다음 장이다.

14 가지 교훈 — 다음 프로젝트로 가져갈 것

전부 incident 또는 audit 결과. backtest 만 잘 나오면 운영 단계에서 비싼 수업료를 낸다.

01
Label 정의는 학습 metric 이 아니라 사용자 행동 가능성 기준
6-class softprob 은 cross-entropy 잘 떨어졌지만 "5-10% class 60%" 가 매매 결정으로 안 이어짐. h2/h5/h6 처럼 "4h 안 +3% 이상" 같은 actionable label 로 재정의하자 알림이 비로소 행동 가능해졌고 hit·농축 엣지가 살아났다 — 단 자동 net 흑자는 끝내 아니었다(§Status).
02
Train ↔ Live mismatch 는 backtest 에서 안 보인다
Pre-open daily features 는 학습 데이터에서 fully closed 였지만 live 08:55 에서 5min partial. 양쪽 다 closed 인 backtest 는 mismatch 안 잡음. 15m precursor only 로 좁힘.
03
단일 점수 → 조건부 분포로 가면 사용자 판단이 가능해진다
"≥20% tail 후보" 한 줄은 timing 모호. h2/h6/h5 + setup 분해하니 알림이 결정 트리 — h2 강 = 즉발, h5 만 강 = tail bonus 관찰.
04
Calibration 안 된 raw probability 는 거짓말 표시
XGBoost predict_proba 0.85 ≠ "85% 확률". h2 top bucket calib error 32.7pp 측정됨. BucketCalibrator 로 historical hit % 만 표시.
05
Bootstrap CI 가 0 을 걸치면 fractional sizing
TP5 path-aware Sharpe diff = +0.18, 95% CI [-0.05, +0.42]. 점추정 양수지만 통계적으로 marginal. full-size X, 1/4-1/8 sizing 으로 보수.
06
Latency 는 운영 spec, backtest spec 아니다
초기 4m 48s. 08:55 발사면 알림이 09:00 이후 도착 = trigger 후 = 의미 없음. recent-window load 로 21s 단축. 정확도 0.001 보다 latency 30× 단축이 더 큰 P&L 기여.
07
Decision-window guard 가 ledger 를 살린다
Manual rerun, systemd catch-up, debugging 시 stale data 로 ledger 가 오염된 incident 가 실제로 있었음. is_preopen_window() / is_decision_window() + --allow-late-* escape hatch 만 명시 manual 인정.
08
진입가 표기는 사소한 UX 가 아니라 close-out 정합성 도구
알림에 진입가 ≈ 일봉 close 표시. paper ledger 의 entry_price_proxy 와 매칭 → close-out 시 실제 첫 15m bar 와 비교해서 slippage / signal-quality 자동 추적. 한 줄 추가가 디버깅 인프라.
09
Silence 는 기능, 침묵 안 하려고 룰을 늘리지 말 것
detector_v1 의 C8-C10 rank fallback ("threshold 통과 0건이면 top-1 알림") 모두 EV 음수. silence-heavy 가 옳음. cap 과 threshold 를 우선하고 BTC regime 은 알림 문맥으로 표시.
10
Premature complexity 회피 — v1 은 단순, v2 는 데이터로 결정
Multi-scale ablation 에서 h5 가 daily+1h+15m 우위였지만 v1 은 daily-only 채택. 1주 live 결과로 ground truth 잡고 v2 swap 결정. 검증 안 된 복잡성을 운영에 넣지 않음.
11
fail-closed 는 fail-loud 와 세트일 때만 안전하다
07-27, 강화된 게이트들이 시스템을 올바르게 멈췄지만 경보가 없어 아무도 몰랐다 — 그리고 v2 는 53일간 "정상 무추천일" 로 위장된 채 굶어 죽는 중이었다. 멈추는 코드보다 멈췄다고 소리치는 코드가 먼저다.
