# 4. 방법론 해부 (c) — 학습·하이퍼파라미터·구현 (부록 B·E)

> **배경 사다리** — ① "epoch"는 학습 데이터를 한 바퀴 다 보는 단위. ② "dead feature(죽은 특징)"는 학습 내내 한 번도 켜지지 않아 쓸모없어진 은닉 유닛. ③ "expansion factor $R$"은 사전이 입력 차원의 몇 배인지(과완비 정도). 이 셋으로 구현 디테일을 읽는다.

## 4.5 이 부분이 왜 필요한가

방법의 수식(05_method_b)은 단순하지만, **희소 오토인코더는 학습이 까다롭다.** 대표적 병목이 dead feature(은닉 유닛이 죽어 사전이 실질적으로 작아짐)와 $\alpha$·$R$ 같은 하이퍼파라미터 민감성이다. 이 절은 원문이 실제로 쓴 세팅과 트릭을 정리한다. 정확한 수치가 원문 표에 없는 항목은 "원문 미보고"로 남긴다.

## 4.6 학습 세팅 (부록 B)

- **활성 데이터 출처**: The Pile(웹텍스트 코퍼스)에서 뽑은 잔차 스트림 활성 벡터. autointerp 채점용 문장은 OpenWebText 앞부분(첫 50,000줄, 64-토큰 조각) 사용.
- **규모**: 활성 벡터 **5–50M개**, **1–3 epoch**. 단일 **A40 GPU 에서 1시간 미만**.
- **최적화기**: Adam, 학습률 $10^{-3}$.
- **대상 모델·지점**: Pythia-70M(잔차 512차원), Pythia-410M(잔차 1024차원). 분석 지점은 **잔차 스트림·MLP 하위층·attention head 하위층**. 주 결과는 잔차 스트림.

## 4.7 과완비 정도 $R$ 과 선택된 $\alpha$

- **$R$(expansion factor)**: 사전 크기 ÷ 모델 차원. 원문이 탐색한 값은 $R\in\{0.5, 1, 2, 4, 8\}$. **주 결과(잔차)는 $R=2$**. Figure 8 은 이 범위에서 해석가능성이 대체로 일관됨을 보고 → "정확한 사전 크기가 결과를 좌우하지 않는다"는 강건성 신호.
- **선택된 $\alpha$**(희소 세기): **잔차 $\alpha=8.6\times10^{-4}$**, **MLP $\alpha=3.2\times10^{-4}$** (부록 E). 이 값들은 "재구성 대 희소"의 매끄러운 tradeoff 상에서 고른 것이며, 앞서 말한 대로 뚜렷한 최적점(knee)은 없음.

## 4.8 dead feature 와 재초기화(neuron resampling)

- 원문은 학습 중 오래 죽어 있는 은닉 유닛을 **주기적으로 재초기화**(모델이 아직 잘 재구성 못 하는 입력 방향으로 되살림)하는 방식을 쓴다 — Anthropic 계열에서 "neuron resampling"으로 알려진 트릭과 같은 취지.
- 그럼에도 **MLP 중간층에서는 dead feature 가 많이 남았고**($\alpha=0$ 이어도), 과완비 사전을 강건히 학습하지 못했다(부록 E, Figure 16). 잔차·attention 층은 $\ge 4\times$ 과완비까지 특징이 살아남았다. → "SAE 는 잔차 스트림에서 잘 되고 MLP 에서 덜 된다"는 실무 교훈의 출처.

## 4.9 다른 설계로 했다면 (대안 2~3개)

- **L1 대신 TopK**: "정확히 $k$개만 켜라"로 희소를 직접 강제 → $\alpha$ knee 문제와 shrinkage(활성 과소추정)를 우회. (후속 Gao et al. 2024, Makhzani & Frey 2013 계열.) 대가: $k$를 층·과제별로 골라야 함.
- **tied weights 해제**: 검출 방향≠재구성 방향을 허용해 표현력↑, 그러나 모호성·메모리 비용↑.
- **재구성 손실 대신 KL 손실**: "복원값을 넣었을 때 모델 출력이 얼마나 변하나(KL)"를 직접 최소화 → 원문 §6.2 가 스스로 제안한 방향. 재구성은 잘 되지만 기능적으로 중요한 방향을 놓치는 문제를 겨냥.

## 4.10 의사코드 (개념 수준 재구성 — 원문 절차의 요약)

```python
# 원문 §2 + 부록 B 를 개념적으로 옮긴 것 (원문에 이 코드 형태로는 없음)
M = row_normalized_init(d_hid=R*d_in, d_in)   # 사전 행렬, 행 정규화
b = zeros(d_hid)
for step in range(steps):
    x  = sample_activations(model, dataset=The_Pile)   # 잔차 활성 배치
    c  = relu(M @ x + b)                               # Eq.1 인코더
    xh = M.T @ c                                       # Eq.2 디코더 (tied)
    loss = mse(x, xh) + alpha * L1(c)                  # Eq.4
    adam_step(loss); renormalize_rows(M)               # 행 정규화 유지
    if step % resample_every == 0:
        resample_dead_features(M, b)                   # dead feature 되살림
```

## 4.11 이 부분의 핵심 한 문장

> **구현의 성패는 "dead feature 관리 + $\alpha$·$R$ 선택 + 어느 지점(잔차 vs MLP)에 붙이느냐"에 달려 있으며,** 이 논문이 남긴 가장 실용적인 교훈은 "**잔차 스트림에 $R{=}2$ 로 붙여라, MLP 는 아직 어렵다**"는 것이다.
