# 4. 방법론 해부 (a) — 큰 그림: 왜 "희소 오토인코더"인가

> **배경 사다리** — ① "활성 벡터(activation vector)"는 모델이 한 토큰을 처리할 때 특정 층에서 내놓는 숫자 목록(예: 512개 숫자)이다. ② "잔차 스트림(residual stream)"은 트랜스포머에서 각 층이 정보를 더하고 빼가는 공용 게시판 같은 벡터 통로다. ③ "오토인코더(autoencoder)"는 입력을 한 번 압축했다 되펼쳐 **원본을 최대한 복원**하도록 학습하는 신경망이다. 이 셋만 알면 이 절을 읽을 수 있다.

## 4.1 한 문단 요약 (다이어그램 지문)

그림으로 그리면 이렇다.

```
언어모델(Pythia)  ──▶  잔차 스트림 활성 x  (예: 512차원)
                              │
                              ▼
                 [ 인코더 ]  c = ReLU(Mx + b)     ← 특징 활성 (예: 1024차원, 대부분 0)
                              │   (희소: 소수만 켜짐)
                              ▼
                 [ 디코더 ]  x̂ = Mᵀ c            ← x 를 되살린 값
                              │
                              ▼
        손실 = ‖x − x̂‖²  +  α‖c‖₁
              (똑같이 복원)   (조금만 켜라)
```

핵심 발상은 두 압력의 **줄다리기**다. 왼쪽 항 $\lVert x-\hat{x}\rVert_2^2$ 은 "원본을 똑같이 복원해"라고 밀고, 오른쪽 항 $\alpha\lVert c\rVert_1$ 은 "그걸 최대한 **적은 수의 특징만 켜서** 해내"라고 민다. 이 줄다리기의 균형점에서, 은닉 유닛(특징)들은 "자주 함께 등장하는 활성 패턴"을 하나씩 전담하게 되고 — 그게 바로 우리가 찾던 **단의미 방향**이다.

## 4.2 왜 하필 이 형태인가 (대체 설계와 비교)

- **왜 뉴런을 그냥 안 읽고 새 오토인코더를 학습하나?** 뉴런 축은 중첩 때문에 다의적이다(03_problem 참조). 우리가 원하는 건 "모델이 실제로 정보를 싣는 방향"이지 "우리가 임의로 고른 좌표축(뉴런)"이 아니다. 오토인코더의 은닉 방향은 **데이터가 정해준** 좌표축이다.
- **왜 은닉 차원이 입력보다 큰가(과완비, overcomplete)?** 중첩 가설의 전제가 "특징 수 > 뉴런 수"이기 때문이다. 512차원에 512개 방향만 허용하면(완비) 애초에 중첩된 특징을 다 담을 수 없다. 그래서 $R>1$ (예: $R=2$ → 1024개) 로 방향을 늘린다.
- **왜 희소성(L1)을 강제하나?** 희소성이 없으면 "아무 방향이나 조금씩 다 켜서" 원본을 복원하는 무의미한 해가 나온다. "한 번에 소수만 켜라"는 압박이 있어야 각 방향이 **독립된 뜻**을 갖도록 특징이 분리된다. 이것이 Olshausen & Field(1997) 희소 코딩의 핵심 통찰을 트랜스포머에 이식한 것이다.
- **PCA/ICA 로 하면?** 둘 다 완비 선형 분해라 과완비가 안 되고(방향 수 ≤ 차원 수), 분산·독립성을 최적화할 뿐 해석가능성을 목표로 하지 않는다. 그래서 baseline 으로만 쓰이고 진다(Figure 2).

## 4.3 전체 파이프라인 3단계

1. **특징 사전 학습** (§2, 05_method_b): 잔차 활성 $x$ 로 위 오토인코더를 학습해 사전 행렬 $M$ 을 얻는다. $M$ 의 각 행이 특징 방향 $f_i$.
2. **자동 해석** (§3, 06_experiments_a): 각 특징 $i$ 가 언제 켜지는지 문장을 모아 큰 LLM 에게 설명·재현시켜 해석가능성 점수를 매긴다.
3. **인과 개입** (§4~5, 06_experiments_b): IOI 과제에서 특정 특징 계수를 반사실 값으로 바꿔치기(활성 패칭)해 출력이 예측대로 바뀌는지 본다.

## 4.3-bis 왜 하필 "잔차 스트림"에 붙이나

트랜스포머에는 활성을 읽을 지점이 여럿이다(attention 출력, MLP 은닉, 잔차 스트림). 저자들이 주 결과로 **잔차 스트림**을 고른 데는 이유가 있다. 잔차 스트림은 각 층이 정보를 **더하고 빼는 공용 게시판**이라, 모델이 "다음 계산으로 넘기려고 실제로 들고 있는 정보"가 모이는 곳이다. 즉 특징이 **읽고 쓰이는** 자연스러운 통로다. 반면 MLP 중간 은닉은 그 층 내부의 임시 계산이라 구조가 더 얽혀 있고(실제로 SAE 학습이 실패, 05_method_c §4.8), attention 출력은 위치기하가 섞여 있어 선형 사전으로 담기 어렵다. 이 "어느 지점에 붙이나"의 선택은 뒤(07_limits, 09_my_research)에서 **APF 가 겨냥하는 attention 기하와 SAE 가 읽는 잔차 방향의 좌표계 경쟁**으로 되돌아온다.

## 4.4 이 부분의 핵심 한 문장

> **"모델을 읽는 좌표계를 뉴런에서 '데이터가 정해준 과완비 희소 사전'으로 갈아끼우는 것"** — 그게 이 방법의 전부이며, 나머지(해석·인과)는 그 좌표계 위에서 자연히 따라온다.
