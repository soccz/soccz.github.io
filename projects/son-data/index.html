Overview

두 시점의 분석

학부 시절의 분석 원칙은 분명했습니다. "결과를 먼저 라벨링하고, 변수들을 통계적으로 검증한 뒤, 그 검증값을 가중치로 인코딩에 반영한다." 지금 다시 보면, 이 사고 흐름은 통계학적으로는 옳았지만 ML 모델 검증 관점에서 누수와 충돌하는 지점이 있었습니다. 이 페이지는 그 충돌을 회피하지 않고 정면으로 기록합니다.

당시의 의도
"문자→숫자 인코딩은 통계적으로 유의미한 관계를 반영해야 한다." 결과 라벨을 기준으로 변수의 영향력을 OLS p-value로 측정하고, 그 값을 인코딩 가중치로 사용했습니다.
지금의 시선
전체 데이터의 result 평균을 피처에 박아 넣은 그 인코딩이, ML 관점에선 가장 큰 데이터 누수였습니다. 통계학자의 옳음과 ML 모델러의 옳음이 갈라지는 지점.
회고의 가치
방향은 맞았습니다. 다만 검증 위생 한 줄씩이 빠졌습니다. 어떤 줄이 빠졌고, 어떻게 채우면 의도가 살아남는지를 9가지 수정 항목으로 정리합니다.
한 줄 요약

이 프로젝트의 사고 흐름은 통계학적으로는 정밀했지만, ML 검증 위생에서 한 단계가 빠졌습니다. 이 페이지는 5가지 의도된 선택과 9가지 회고 수정 사이의 거리를 기록합니다.

5가지 의도된 선택

default 한 줄로 끝낼 수 있는 자리에서 한 단계 더 들어갔던 5가지 결정. 각각이 이 프로젝트의 정체성이자, 지금 다시 본다면 발목을 잡았던 지점이기도 합니다.

Decision 01 · Centerpiece
venue 라벨을 "결과 평균 가중치"로 인코딩
"라벨값 0/1/2가 result에 미치는 영향은 동등하지 않다. 그렇다면 그 영향력 자체를 라벨값에 반영하자."
Home/Away/Neutral을 단순 정수 0/1/2로 두지 않았습니다. 먼저 OLS로 venue가 result에 통계적으로 유의한지 검정한 뒤, venue별 result 평균(0.608 / 0.339 / 0.235)을 그 라벨의 값으로 매핑했습니다. 매핑 후 다시 OLS로 R² 향상을 확인하는 검증 루프까지 거쳤습니다.
# 1단계: OLS로 venue의 통계적 유의성 검정 X_venue = sm.add_constant(data[['venue']]) model = sm.OLS(y_result, X_venue).fit() # → p-value 확인 후 "venue는 result에 유의미" # 2단계: venue별 result 평균을 가중치로 매핑 mean_result_by_venue = data.groupby('venue')['result'].mean() venue_weights = {0: 0.608, 1: 0.339, 2: 0.235} data['venue'] = data['venue'].map(venue_weights)

Decision 02
Custom KNN Imputer (sklearn 그대로 안 쓰고 직접 구현)
"라이브러리 한 줄로 끝나는 결측 처리에서, categorical을 어떻게 다룰지 직접 설계해보자."

KNNImputerfactorizemedian + mode fallback 지금 시선: factorize 거리 의미 약함
Decision 03
변수 선택을 "선형 + 비선형 + 통계검정" 3단으로
"상관 관계는 선형만 본다. 비선형도 봐야지. 거기에 통계적 유의성까지 검정하자."
한 가지 기준에 의지하지 않았습니다. (1) Correlation matrix로 선형 관계, (2) Random Forest feature_importances_로 비선형 관계, (3) t-test로 통계적 유의성. 세 단계를 모두 통과한 변수만 최종 모델에 투입했습니다.
# Stage 1: 선형 — 상관 관계 매트릭스 correlation_matrix = data_clean.corr() result_corr = correlation_matrix['result'].sort_values(ascending=False) # Stage 2: 비선형 — Random Forest 중요도 rf = RandomForestClassifier(n_estimators=100, random_state=42) rf.fit(X_scaled, y) top_features = X.columns[rf.feature_importances_.argsort()[::-1]][:6] # Stage 3: 통계 검정 — t-test (유의수준 5%) for feature in top_features: t_stat, p_value = ttest_ind(X[feature][y==1], X[feature][y!=1]) if p_value < 0.05: significant_features.append(feature)

Decision 05
PCA에 Varimax 회전을 직접 구현해 적용
"PCA로 차원만 줄이지 말고 각 컴포넌트가 무슨 의미인지도 알자."
factor_analyzer.Rotator가 있는데도 SVD 기반 Varimax 함수를 직접 짰습니다. 회전 후 |loading| > 0.5인 변수만 골라 각 컴포넌트의 의미를 해석 가능한 그룹으로 만드는 시도. 보통 ML 입문자는 PCA → 그대로 모델에 넣지만, 여기선 EFA(탐색적 요인 분석)의 사고로 한 단계 더 들어갔습니다.

R = np.dot(u, vh) return np.dot(Phi, R) # 회전된 로딩에서 |값| > 0.5인 변수만 추출 for i, component in loading_df.iterrows(): significant_vars = component[component.abs() > 0.5]

5가지 결정의 공통 패턴

전부 "default가 아니라 한 단계 더 들어간다"는 패턴입니다. 통계학적 사고(p-value, 가중치, 회전)와 엔지니어링적 욕심(직접 구현, 페이지 파싱)이 둘 다 보입니다. 5가지 모두 의도는 옳았지만, 5가지 중 4가지가 ML 검증 위생 한 줄씩이 빠져 결과가 깨졌습니다. 다음 두 섹션에서 그 거리를 좁혀갑니다.

Centerpiece

Venue 가중치 인코딩 — 4단 사고흐름

이 프로젝트의 핵심 디자인 결정. 결과 라벨링 → 통계 검증 → 가중 매핑 → 재검증의 4단계로 구성됩니다. 한국 학부 교과 과정에서 보기 드문 사고 깊이이지만, 동시에 가장 큰 누수 원인이기도 했습니다.

1
결과 라벨링 — Win/Drew/Loose → 1/0/-1
분석의 출발점. 결과 변수를 승부의 부호를 살린 정수 라벨로 바꿉니다. 단순 0/1/2가 아니라 -1/0/1로 둔 이유는, OLS 회귀 시 "결과의 방향성"이 자연스럽게 모델에 들어가기를 원했기 때문입니다.
result_mapping = {'Drew': 0, 'Loose': -1, 'Win': 1} son_stats_df['result'] = son_stats_df['result'].map(result_mapping)
2
통계 검증 — OLS p-value로 변수 영향력 측정
venue를 인코딩하기 전에, 그것이 result에 정말 통계적으로 유의한지 OLS로 먼저 검정합니다. 비교군으로 game_started도 같이 검정해 "유의하지 않다"는 결론을 직접 확인. 인코딩 결정에 통계가 선행하는 구조입니다.
# venue 검증 X_venue = sm.add_constant(data[['venue']]) model_venue = sm.OLS(y_result, X_venue).fit() # → p-value 작음 → "유의미함" 판정 # 비교: game_started 검증 X_gs = sm.add_constant(data[['game_started']]) model_gs = sm.OLS(y_result, X_gs).fit() # → p-value 큼 → "유의미하지 않음" 판정 → 가중치 매핑 적용 안 함
3
가중 매핑 — 라벨값을 result 평균값으로 치환
venue별 result 평균을 구한 뒤, 그 평균값 자체를 라벨의 새로운 값으로 사용합니다. 0/1/2 정수가 아니라 0.608/0.339/0.235로 매핑되면, 이후 모든 모델은 venue 한 컬럼만 봐도 "그 venue에서의 평균 승률"을 직접 입력으로 받게 됩니다.
mean_result_by_venue = data.groupby('venue')['result'].mean() # Home: 0.608, Away: 0.339, Neutral: 0.235 venue_weights = {0: 0.608, 1: 0.339, 2: 0.235} data['venue'] = data['venue'].map(venue_weights)
4
재검증 — 매핑 후 R² 향상 확인
가중 매핑이 모델 적합도를 정말 개선하는지 다시 OLS를 돌려 R² 변화를 확인합니다. "검증 → 변환 → 검증"의 닫힌 루프를 만든 것이 이 프로젝트의 가장 정밀한 부분입니다.
X_weighted = sm.add_constant(data[['venue']]) model_weighted = sm.OLS(y_result, X_weighted).fit() # → R² 비교: 정수 인코딩 vs 가중 인코딩 # → 가중 인코딩이 더 높은 R² → 인코딩 채택
지금의 시선 — 통계학자의 옳음 vs ML 모델러의 옳음

이 4단 흐름은 통계 모델링 관점에선 정석입니다. 변수의 영향력을 측정하고 그것을 인코딩에 반영하는 건 회귀 분석의 정상적인 절차예요. 하지만 예측 모델 관점에선 이게 가장 큰 데이터 누수였습니다. data.groupby('venue')['result'].mean()은 train과 test를 가리지 않은 전체 데이터의 result 평균을 사용했고, 그 결과 venue 피처는 사실상 "이 venue에서의 정답 평균"이라는 답지에 가까운 값이 되었습니다. 모델은 이 답지를 보고 학습되었기 때문에, 정확도가 부풀려진 채로 나옵니다.

"선형(LR) / 트리(RF) / 커널(SVM) 세 패러다임을 같은 변수 위에서 5-fold CV로 비교한다."

Retrospective

지금 다시 본다면 — 9가지 수정

위 5가지 의도된 결정의 방향은 살리되, ML 검증 위생을 보강하는 9가지 수정. 우선순위는 결과의 신뢰도에 미치는 영향 순입니다.

Critical
Crawler step=2 → step=1 (시즌 절반 누락)
fbref URL /{year}-{year+1}/는 한 시즌(예: 2011-12)을 의미. 그런데 range(2011, 2024, 2)로 두면 2012-13, 2014-15, 2016-17, 2018-19, 2020-21, 2022-23 시즌이 통째로 빠집니다. 손흥민 토트넘 전성기의 절반이 빠진 데이터로 모든 후속 분석이 진행된 셈. 모든 결과의 토대를 흔드는 가장 큰 결함.
crawler.ipynb · URL 패턴 재해석
Critical
Venue Target Encoding → train fold 안에서만 평균 계산
전체 데이터의 result 평균을 venue 라벨에 박아 넣은 인코딩은 데이터 누수. 의도(통계 가중치)는 살리되, CV 안에서 매 fold마다 train 부분만으로 평균을 다시 계산해 매핑하는 식으로 한 줄 위치만 변경하면 됩니다.

Lesson

통계학자의 사고 vs ML 모델러의 사고

이 회고에서 배운 가장 큰 한 가지. 두 사고방식은 충돌하는 게 아니라, 적용되는 층위가 다릅니다.

통계학자의 사고
주어진 데이터셋 안에서 변수 간의 관계를 추정하고 검정합니다. p-value, R², OLS는 "이 데이터에서 이 가설이 얼마나 지지되는가"의 언어. 전체 데이터를 보는 것이 자연스럽고, 그것이 정상적인 추론 절차입니다.
ML 모델러의 사고
보지 못한 데이터에서 모델이 얼마나 잘 작동하는지가 전부입니다. train/test, CV fold, time-series split은 "테스트셋이 정말 미래/외부의 데이터인가"를 보장하는 절차. 어떤 통계량도 fold 경계를 넘으면 누수가 됩니다.
두 사고의 통합
이 프로젝트의 4단 사고흐름은 통계학자의 절차로는 정석입니다. 다만 그것을 ML 파이프라인에 옮길 때, 모든 통계 연산을 train fold 안으로 가두면 의도가 살아남으면서 누수가 사라집니다. 둘 중 하나를 버리는 게 아니라, 위치를 한 단계 옮기는 일.
3년의 거리

학부 시절의 사고 흐름을 폐기하지 않는 회고가 가능한 이유는, 그 흐름이 통계적으로 옳기 때문입니다. ML 검증 위생을 알게 된 지금, 그 옳음을 살리기 위해 필요한 것은 큰 재설계가 아니라 코드 한 줄의 위치 변경입니다. 이 단순한 차이를 인식하는 데 3년이 걸렸고, 다음 버전에서 그 거리를 좁힙니다.

v2가 측정한 결과 — 회고의 회고

이 회고에도 두 가지 정정이 필요했습니다

v2 페이지(son-data-v2)에서 6개 실험으로 같은 데이터에 v1과 v2를 동시에 적용했습니다. 그 측정 결과로 이 회고 페이지의 두 가지 framing이 정정 대상이 되었습니다. 회고도 회고의 대상이 됩니다.

정정 01
"누수가 v1의 결함"이라는 단순화
"이 회고는 9가지 수정 항목에서 'Critical: target encoding leakage'와 'Critical: scaler leakage'를 강조했지만, v2의 진단 실험은 그것이 단순화된 framing이었음을 보여줍니다."
v2 Part 6 (v1 collapse 진단)에서 v1을 한 줄씩 변형해 측정한 결과: scaler leakage 단독으로는 collapse에 영향이 0이었고, target encoding 제거도 부분 효과만 있었습니다. v1이 모든 경기를 W로 예측한 진짜 chord는 RF top_k=6 feature selection × 클래스 불균형 × accuracy 기준 GridSearch의 3중 조합이었습니다. class_weight='balanced' 추가 + scoring=f1_macro만으로도 W rate 100% → 39%로 떨어집니다. "누수 제거"가 아닌 "불균형 처리 + 피처 다양성 + 적절한 metric"이 진짜 fix.

"적응 곡선 회복 시간 차이"의 통계적 견고성

정정에도 불구하고 살아남은 것 — 4단 사고 흐름 전부

두 정정에도 불구하고, 이 회고의 핵심 narrative — "4단 사고 흐름은 살리고 적용 위치만 옮긴다" — 는 v2의 측정으로 모두 검증되었습니다. ① 결과 라벨링 ✓ ② venue OLS 통계 검증 ✓ (인과 추론으로 격상) ③ venue 가중 인코딩 ✓ (Ablation/SHAP/Bayesian 3중 검증) ④ R² 재검증 ✓ (TimeSeriesSplit F1 + HDI). 학부 시절의 통계학적 직관은 살아남았고, 단지 회고 자체의 framing이 한 단계 더 정교화되었을 뿐입니다.

더 자세한 측정 과정과 6개 실험의 결과는 son-data-v2 보고서를 참조하세요. v1과 v2를 같은 627경기에 동시에 적용한 정량 비교, Feature Ablation, v1 collapse 진단, Cross-league 전이, Counterfactual venue, Bayesian 계층 모델, 다른 prediction target 실험을 단계별로 풀어 썼습니다.
